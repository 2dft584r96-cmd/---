# Размещение на собственном сервере

Конфигурация: Docker Compose, Node.js 24, SQLite на постоянном томе, Caddy с автоматическим HTTPS. Приложение не открывает порт 3000 наружу. Публичными становятся только HTTP/HTTPS. Доступ к переписке и файлам требует аккаунта, регистрация сотрудников — приглашения.

## Требования

Linux-сервер с Docker Engine и Docker Compose v2, доступом к Docker Hub и центру сертификации, домен с A-записью на IP сервера (и корректной AAAA, если она задана). Открытые порты 80/443. Эти порты должны быть свободны; если уже работает nginx/Caddy, используйте существующий прокси, не останавливая чужие сайты. Конфигурация ниже предназначена для выделенного домена и свободных портов. Фактические DNS и сервер проверяются перед запуском.

## Первый запуск

1. Разместите исходники проекта на сервере. Не копируйте локальные `data/`, `.env`, `node_modules/` или тестовые базы.
2. В каталоге проекта выполните:

   ```sh
   bash deploy/prepare.sh team.example.ru
   docker compose up -d --build
   docker compose ps
   ```

   Замените `team.example.ru` вашим доменом. Скрипт создаёт секретный код администратора в `.env` с правами 600 и отказывается перезаписывать существующую конфигурацию.

3. Проверьте HTTPS-запрос `GET /api/health` на вашем домене: ожидается `{"ok":true}`. Сертификат должен быть доверенным, без отключения TLS-проверки.
4. Откройте домен, нажмите «Создать пространство». Введите код из `SETUP_TOKEN` в `.env`, свою почту, имя и пароль. Не передавайте код коллегам: он нужен только первому администратору. Дальнейшая регистрация — по отдельным одноразовым приглашениям.
5. Проверьте вход, обмен сообщениями и файлами двумя сотрудниками, затем перезапустите `docker compose restart app` и проверьте сохранность данных.

`.env` содержит секрет. Не отправляйте его в чат, Git или систему логирования. Сохраняйте SETUP_TOKEN в конфигурации: production-процесс требует его при каждом запуске, но создание второго первого администратора запрещено сервером.

## Обновление

```sh
docker compose up -d --build
```

Том `messages` остаётся на месте. Не выполняйте `docker compose down -v`: это удаляет переписку и файлы. Используйте один экземпляр приложения для SQLite.

## Резервная копия

В согласованное время кратковременно остановите приложение и скопируйте весь каталог данных в архив, доступный только администратору:

```sh
umask 077
mkdir -p backups
docker compose stop app
docker compose cp app:/app/data "backups/data-$(date -u +%Y%m%dT%H%M%SZ)"
docker compose start app
```

При ошибке копирования всё равно запустите приложение и устраните причину. Копию храните также отдельно от сервера. SQLite содержит сообщения, файлы, аккаунты и сессии. Для восстановления остановите приложение, восстановите каталог данных с владельцем UID 1000, затем запустите и проверьте приложение. Регулярность и срок хранения резервных копий определяет администратор.

## Файлы

До 10 МБ на один файл. Вложения хранятся в SQLite, поэтому входят в общую резервную копию. Файлы личного разговора доступны только участникам этого разговора; список файлов тоже фильтруется. Скачивание идёт как вложение (`application/octet-stream`), пользовательский HTML не исполняется внутри приложения. Антивирусная проверка и квоты общего объёма пока не реализованы; следите за свободным местом на диске. В разделе отображаются последние 200 доступных файлов.

## Диагностика

`docker compose logs --tail=100 app proxy` — ошибки запуска и выдачи сертификата. Не публикуйте логи с личной информацией. Если HTTPS не работает, проверьте DNS, доступность 80/443 и отсутствие другого процесса на этих портах. Не обходите проверку сертификатов.
