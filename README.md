# АПЕКС-РАДИО · Команда

Русскоязычное рабочее пространство для сотрудников радиостанции. Каналы, личные сообщения и обсуждения в фирменном оформлении из предоставленного медиа-кита АПЕКС-РАДИО.

## Запуск

Нужен Node.js 24 или новее. В каталоге проекта:

```sh
npm ci
npm start
```

Сервер по умолчанию слушает `127.0.0.1:3000`. Приложение использует встроенные модули Node.js и SQLite; внешних зависимостей для работы сервера нет. Playwright — только инструмент проверки интерфейса.

Для собственного сервера подготовлены [Docker Compose и инструкция HTTPS](deploy/README.md).

На первом открытии показана **демонстрация** с вымышленными сотрудниками и сообщениями. Она работает в памяти браузера, не попадает в базу и сбрасывается при перезагрузке.

1. Нажмите «Создать пространство» и создайте аккаунт администратора. Сделайте это до предоставления сетевого доступа другим людям: первый зарегистрированный пользователь становится администратором.
2. Нажмите «Пригласить коллегу». Передайте сотруднику адрес развёрнутого приложения и одноразовый код. Код действует 24 часа.
3. Коллега выбирает «Войти в пространство» → «Есть приглашение? Присоединиться» и регистрируется с этим кодом.
4. Используйте каналы для общей переписки, кнопку «Команда» для личного разговора, значок обсуждения для ответов, закладку для сохранения сообщения. Поиск работает по переписке, доступной текущему сотруднику.

## Возможности первой версии

- Полностью русские интерфейс, ошибки, подсказки и формы входа.
- Каналы «общий», «эфир», «редакция», «музыка» и создание новых каналов.
- Личные разговоры двух участников с проверкой доступа на сервере.
- Раздел «Файлы»: загрузка до 10 МБ, скачивание и права доступа по разговору.
- Сообщения и ответы, шесть реакций, личные закладки, регистронезависимый поиск на русском.
- Обновление переписки каждые три секунды при открытой вкладке.
- Счётчики непрочитанного, черновики при переключении каналов, адаптивная версия для телефона.
- Постоянное хранение в SQLite, хеширование паролей scrypt, HttpOnly-сессии, защита от запросов с чужого Origin, ограничение попыток входа, экранирование пользовательского текста и Content Security Policy.

## Проверки

```sh
npm run check
npm test
npm run test:browser
```

`npm test` выполняет семь интеграционных сценариев на отдельной временной базе: вход и приглашения, сообщения и ответы, поиск и реакции, приватность личных разговоров, каналы и перезапуск сервера.

Браузерный тест использует Chromium по пути `/usr/bin/chromium`; другой путь можно задать через `CHROMIUM_PATH`. В облачной среде Chromium уже установлен. Тест запускает собственный сервер со временной базой, проверяет демонстрацию и работу двух реальных аккаунтов. Скриншоты можно сохранить, задав `ARTIFACT_DIR`. Рабочие аккаунты и база этим тестом не затрагиваются.

## Настройки и хранение

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `HOST` | `127.0.0.1` | Адрес прослушивания |
| `DB_PATH` | `data/apex.sqlite` | Путь к постоянной базе |
| `SETUP_TOKEN` | не задана | Секретный код первого администратора; обязателен в production (минимум 32 символа) |
| `COOKIE_SECURE` | не задана | Значение `1` включает Secure для cookie при работе через HTTPS |

Для доступа коллег нужен сервер с постоянным диском и HTTPS-прокси. При публикации укажите `COOKIE_SECURE=1`, сохраните исходный заголовок `Host` в прокси и подключите постоянный каталог данных. `HOST=0.0.0.0` нужен только для прослушивания сетевых интерфейсов в вашей инфраструктуре. Публичное размещение требует адреса сервера, домена и доступа администратора.

Резервное копирование: остановите процесс приложения и сохраните весь каталог `data/` (включая файлы SQLite WAL, если они присутствуют). Каталог содержит частную переписку и сессии; не добавляйте его в Git. Для восстановления остановите сервер, восстановите каталог и запустите приложение. Публикация снимка облачной среды не заменяет резервное копирование рабочей базы.

Проверка готовности: `GET /api/health` возвращает `{"ok":true}`. Процесс надо запускать заново после восстановления среды.

## Границы первой версии

Это самостоятельный рабочий прототип основных сценариев Slack, а не полная замена его инфраструктуры. Пока нет звонков, push-уведомлений, закрытых каналов, редактирования и удаления сообщений, восстановления пароля, управления увольнением сотрудников и корпоративного SSO. Все каналы открыты участникам пространства; личные сообщения изолированы. Сквозное шифрование не реализовано, оператор сервера имеет доступ к базе.

В разговоре отображаются последние 1000 сообщений; поиск выдаёт до 100 результатов. Пагинация истории и масштабирование на большие организации не реализованы. До запуска в постоянную эксплуатацию нужны развёртывание, политика хранения, резервное копирование и административные операции под процессы вашей команды.

Фирменные источники и принципы интерфейса описаны в [docs/DESIGN.md](docs/DESIGN.md).
